## MOD7C - the PROLOGUE (emitted statements 0-14), the EPILOGUE (20-22) and THE TRIPLE

Everything in this section is an EMITTED-SIDE contract, exactly as MOD7 and MOD7B labelled the five
block lemmas: it says what the emitter's own 'GenAst.qArmBodyModarith7' computes, and it is NOT an
equation against 'modarith7Form' and implies none.

THE TOUCH ORDER OF THE PROLOGUE, DERIVED (not guessed) from 'Step.argsCons' evaluating the REST before
its head ('BigStep.lean:209-212'). The prologue is the one region of this arm whose reads ARE in source
order, because every read is the only read of its own statement:
  * statement 0  'let q_flags := byte 0 (mload q_pc)'      touch(pc0)
  * statement 4  'q_cond_ptr := shr 240 (mload q_pc)'      touch(pc0+1)          [COND only]
  * statement 6  'let qconst := byte 0 (mload q_pc)'       touch(pcA)            [CONST only]
  * statement 6  'q_acc := mload (q_const_mptr + (qconst<<5))'
        the 'add' argument list is evaluated REST-first, so 'shl 5 qconst' is evaluated BEFORE
        'q_const_mptr' - neither touches memory, so the order is invisible here but the VALUE of the
        address is computed in that order - and then the mload touches 'cm + (qconst<<<5)'  [CONST only]
  * statement 7  'let q_counts_word := mload q_pc'         touch(pcC)
  * statements 8-13 no memory access; statement 14 is the spill guard at the EMPTY stack and takes the
        FALSE branch, so it touches nothing.
Total: 1 + (COND?1) + (CONST?2) + 1 memory touches, and the cursor
'pcF = pc0 + 1 + (COND?2) + (CONST?1) + 5' - the prologue's own contribution to
'quotientModarith7OpLen' ('VmValidator.lean:626-644'), pinned by 'mod7_prologue_cursor'.

THE FLAG BRANCHES. The two optional fields are 'Step.ifTrue' over a 'Step.block', so the 'let qconst'
inside the CONST branch is 'restore'd away by the block and the ENVIRONMENT SHAPE does not depend on
the flags at all - only the VALUES of 'q_cond_ptr', 'q_acc' and 'q_pc' do. That is why the prologue is
ONE derivation with a two-way split inside each of the two 'yif' links rather than four derivations.
And MOD7B's warning is right: the writes the branches make to 'q_pc' are later OVERWRITTEN by the next
branch and by statement 13, so the collapse is 'venvSet_set_same' / 'venvSet_same_of_get' at the
environment, never a chain lemma.
