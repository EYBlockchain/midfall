## 1. Recommendation in one paragraph

DONE becomes one term, `poseidon_done : Done poseidonFixtureCalldata`, and one command, `#assert_axioms poseidon_done [...] native [...]`, which is a build error until it holds. Progress is the output of one command, `bash scripts/verify.sh --report`, which prints four things generated by tools: the status of every sorried leaf of the headline cone (OPEN, REFUTED, VACUOUS), the executable exhibits (PRESENT or MISSING), the block coverage at the deployment weighted by tokens, and the axiom allow-list verdict. The sorry register is keyed by declaration name and read from the environment. The frozen pin is extended by a closure manifest. In exchange, the eight `#cone_avoids` lines (implied by `#imports_avoid`, J+3) and, by decision, the three v1-only text gates can be retired.

## 2. Deliverable 1: `#assert_axioms` (prototype: `$D/Done.lean`, 685 lines, `import Lean` only; tests: `$D/DoneTest.lean`, `$D/T1.lean`)

Syntax (the keywords `native`, `under`, `allow`, `root`, `at`, `nativeModules` are non-reserved, written `&" native "`; a plain `" native "` token made `native` a keyword and broke the file, and would break `decide +native` downstream):

```lean
#assert_axioms thm [a₁, …]
#assert_axioms thm [a₁, …] native [d₁, …]
#replay_native thm
```

Semantics. `Lean.collectAxioms thm` must be a subset of the named list plus native axioms of listed owners. A native axiom `d._native.native_decide.ax_*` is accepted only if all of these hold:
- `d` is in the `native` list, exists, and is not itself an axiom;
- `d` and the axiom are in the same module;
- the axiom's type is `@Eq Bool e true` with `e` closed (`isNativeShape`);
- the axiom's declaration range lies inside `d`'s range and equals its own selection range (`generatedInside`). `nativeEqTrue` (toolchain `Lean/Meta/Native.lean:75`) records the tactic's syntax range, so a generated axiom sits inside its owner; a hand-written `axiom` command cannot. Measured: `poseidonModel_isOk` 96:0-101:74, its axiom 101:61-101:74; a hand-written one 16:0-16:66 with selection 16:6-16:42.

An allow-list entry that is not an axiom is an error; unused allowances are printed. `#replay_native` compiles and evaluates every native axiom's Bool again and errors if it is not `true`; it is the only check that trusts no name.

The four measures:

(i) Leaf status, registry-free. A refuter is any sorry-free project theorem whose type is `∀ ys, ¬ Q` or `∀ ys, Q → False`.
- REFUTED form 1: the refuter negates the leaf's whole statement. The convention for landing a refutation is `theorem foo_refuted : ¬ type_of% @foo`.
- REFUTED form 2: the leaf has no hypothesis and the refuter negates its conclusion at an instance.
- VACUOUS: a hypothesis of the leaf is negated for every value of the leaf's binders.
- In every case the match must assign every binder of the refuter and, in form 2, of the leaf. Without that rule the first version gave two false VACUOUS verdicts (`calldata_roundtrip`, `decodeAcc_encode_pointPair`) from conditional negations; the fix has a regression test in DoneTest.
- What is realistic: it finds exactly the refutations someone has landed as theorems. `rejects_of_not_accepts` stays OPEN until its refutation is landed. Matching is reducible defeq, so a refutation phrased differently is missed (false negatives only).
- It also sees the v1 failure: `Midfall.Lowering.lowering_equivalence` prints `ROOT IS VACUOUS: hypothesis #17 … refuted for every instance by LegacyVacuity.not_LoweringCorrect`, and the sorried `end_to_end_acc_complete` is the tree's one VACUOUS row.
- Gate form: `#assert_no_refuted_sorry [Midfall]` errors today on `poseidon_valid`. It goes into the report in the ticket that removes that sorry.

(ii) Exhibits. `#exhibits [names]` prints PRESENT or MISSING. The names are the interface to the object and reference areas: `Midfall.Instances.PoseidonExhibit.fixture_returns_abiTrue_ok`, `fixture_leanAccepts_ok`, `mutants_revert_ok`, `mutants_leanRejects_ok`. Each is also an `#eval … -- expect true` line that `kat_gate.py` evaluates. The report only refuses to be silent about an exhibit nobody has written.

(iii) Block coverage. For each constructor of `Partial`, the best project theorem concluding `BlockRow _ _ q`: INTEGRATED (no sorryAx, no undischarged hypothesis, generic or at the render), CONDITIONAL, SORRY, NONE. The row predicate is a parameter, so it survives a change of contract shape. Weights are slice tokens: 0 of 5431 integrated today.

(iv) The axiom allow-list, section 2.

The cone count is kept only as the last check of DONE.

Design choices worth knowing before reading the diffs:

- The closure fingerprint hashes the `Expr` structurally (64-bit, binder names ignored, constants by name), not pretty-printed text. Pretty-printing elides deep terms and changes with notation. Controls: same body with a renamed binder gives the same hash; a changed body gives a different one. Two full runs are byte-identical and the digests were stable over three separate runs.
- The pin is a text manifest (`DECL <module> <decl> <kind> <type hash> <value hash>`), filtered by module prefix, with its sha256 as one more line of `Frozen.sha256`. A change is a diff that names the definition, and the existing W2 mechanism applies unchanged.
- Proposed pinned zone now: semantics, LoweringV2, Lowering support, Assumptions and Common, 972 declarations. The generator, verifier and deployment data are the object V3 repairs; they join at the statement freeze. Pinning them now would force a sign-off on every EMIT ticket.
- The register is keyed by declaration and carries a hash of the statement, so a restated sorry changes its row (J-10). The text scan stays as a cross-check: both scans must name the same modules (19 = 19 today).

## 9. Pitfalls for the implementer

- Tool keywords must be non-reserved (`&" native "`).
- `let mut n := 0` inside a command that builds a `m!` message elaborates as `MessageData`; write `let mut n : Nat := 0`.

- `checks.sh` runs Report.lean twice (closure, then register), about 40 s on a 450 s gate. Cache the output only if that matters.
