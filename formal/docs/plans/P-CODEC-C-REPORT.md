   `hashableG1_readRepr_eq`. Two width-resolution lemmas `logDispatch_at_fr` /

2. `Transcript.LogDecoded E t`: every logged record decodes. Per-primitive steps:

   `read`, `readN`.

   arrayFoldlM, arrayMapM, listForIn, arrayForIn, congr_of_run_eq).
4. The transfer set for every pipeline definition `Pres`/`PresWidths` reach, the two
   do-block walks `presDecoded_parseTrace` / `presDecoded_verifyAlgebraicConstraints`, then
   `presDecoded_prepare`.
5. The consequence the codec lemma consumes: `logDecoded_mapM_some`.

**THE TRAP, handled as designed.** `hashableG1_allowed` holds for EVERY codec - that is its
point, and it was NOT narrowed. `Hashable.Dispatchable E (hashableG1 c)` is false for
`c` other than `E.g1`, so `hashableG1_dispatchable` is stated for `hashableG1 E.g1` alone
and the G1-reading lemmas (`phaseB`, `phaseC`, `multiPrepare`, `readAlgebra`, both walks and
their call sites) CARRY `hg1 : Hashable.Dispatchable E (hashableG1 g1)` and discharge it
once, at `presDecoded_prepare`, where the pipeline codec IS `E.g1`. Perturbation P3 shows
the generalisation is not provable, not merely unproved.

**THE `Pcs` OBLIGATION, same shape as the two existing walks.**
`presDecoded_verifyAlgebraicConstraints` carries
`hpcs : forall queries, PresDecoded E (pcs.multiPrepare queries)`, discharged at
`presDecoded_prepare` by `PresDecoded.multiPrepare` for `Pcs.kzg`. Nothing was attempted
for an arbitrary `pcs`.

**A FINDING THE PLAN DID NOT PREDICT.** `LogDecoded E` is not merely a third invariant
beside `LogWidths`: it is STRONGER. `Transcript.logDecoded_imp_logWidths` proves
`LogDecoded E t -> LogWidths t` (a record whose width the dispatch does not reach for has
no decoder at all), and `logWidths_not_logDecoded` (P-CODEC-B) refutes the converse. So
the third walk subsumes the second for the codec lemma. The `PresWidths` walk was kept
anyway: it is already proved, and `decodeRust_recorded` / `msgWire_logDispatch` are stated
against `LogWidths`.

```
Hint: Omit it from the simp argument list.
```

is such a line. So an UNUSED `simp` argument anywhere in a file that has `#eval` gates makes

cleaned up. Consequence for anyone adding lemmas to a KAT-bearing file: keep new proofs
free of unused-simp-argument warnings, or the failure looks like a phantom extra `#eval`.

## REQUIRED FINDING: what stands between here and the frozen statement

**Yes.** With `verifyNative_iff_msgs_codec` discharged, the frozen
`Midfall.Statements.verifyNative_iff_msgs` is provable modulo ONLY the deliberate
`Statements.lean:68` hold-out. Nothing else is missing: the frozen statement and the
restatement are the same proposition, and the restatement is now a theorem. Filling it is
one line at the frozen arity:

```lean
theorem verifyNative_iff_msgs (hc : E.g1.compressedRoundtrip) : ... :=
  Midfall.Lowering.verifyNative_iff_msgs_codec E F params vk inst pi hc
```

What that one line costs, item by item - which is why it is a decision and not a task:

1. **An import.** `Statements.lean` does not currently import `Midfall.Lowering.Obligations`.
   Adding it is acyclic (no file in the repository has `import Midfall.Statements`, so
   nothing can cycle back), but it makes the frozen spec surface depend on the proof layer
   for the first time. That is itself a policy change: D-P27 stated reason for keeping the
   frozen texts as `sorry` is that the spec surface holds statements, not proofs.
2. **A re-pin.** `checks.sh` runs `sha256sum -c Midfall/Statements.sha256`. Any edit to
   `Statements.lean` reddens that section until the digest is re-pinned, and the file
   header says a re-pin needs a sign-off. D-P27 is the only sign-off so far and it was
   obtained for AMENDING FALSE TEXT, not for filling a proof.
3. **The statement-fingerprint gate does NOT move.** `check_statement_fingerprints.py` cuts
   each declaration at the first top-level `:=` and matches fragments inside the TYPE only
   (`STATEMENTS_PINS`, `STATEMENTS_EXACT`, `STATEMENTS_BINDERS`). Filling the `sorry` changes
   the value, not the type, so all 158 fragments and the three exact pins stay green
   untouched. That is deliberate on both sides: the gate protects what the statement SAYS.
4. **The frozen-axiom gate DOES move, and by design.** `check_frozen_axioms.py` requires each
   of the three pinned statements to depend on EXACTLY
   `[propext, sorryAx, Classical.choice, Quot.sound]`. Its own docstring says the exact-set
   rule exists precisely to catch a statement LOSING an axiom, which is what happens when
   someone fills a `sorry`. So filling `verifyNative_iff_msgs` drops `sorryAx` from that
