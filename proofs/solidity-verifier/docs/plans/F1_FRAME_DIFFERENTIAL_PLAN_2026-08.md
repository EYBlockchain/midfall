# F1 — Close the native-code certification gap: revm frame differential + adversarial shape corpus

## Context

Audit finding F1 (Assurance — High): the render-time certification (`certify_quotient_program`, `src/lowering/quotient_numerator/vm/certify.rs:129-225`) proves bytecode ↔ `QuotientExpr` agreement only for identities lowered to the compact VM. The other five execution surfaces — inline gate prefix, knapsack-selected native gate callbacks, the structured permutation kernel (chunked z-products, delta walk), the structured LogUp kernel (prefix/suffix product tables), and the trash tail — are certified *positionally only* (`certify.rs:176-213`; the dual build pushes `Fq::ZERO` at native positions, `:355-360`). Their arithmetic — the most intricate hand-written Yul in the system — rests on template review plus an env-gated trace differential over a small fixture corpus. The repo already scopes this work as **P2.5** (`docs/plans/REDESIGN_PROPOSALS_2026-08.md:444-456`) and ranks it #1 in `docs/plans/TESTING_STRATEGY.md` §15.

**Why this is incremental** (verified in source):
- `templates/contracts/Halo2QuotientEvaluator.sol` is already a pure function of a raw memory frame: `fallback()` requires `calldatasize() == QUOTIENT_FRAME_LEN`, `calldatacopy`s to `QUOTIENT_FRAME_BASE`, runs the *same* `QuotientHelpers.yul` + `QuotientNumeratorBlock.yul` includes as the monolithic verifier, and returns `[QUOTIENT_MAGIC, -nu_y(x), selector_buckets..]`. No proof, no transcript, no PCS. `render_quotient_evaluator(RenderDiagnostics)` is public (`src/builder/render.rs:64`).
- Every `QuotientIdentity` on every surface carries a populated `.expr` (`vm/mod.rs:322-344`) — the oracle exists; `certify::interpreted_exprs` merely filters it to interpreted items.
- The EVM harness has everything needed: `compile_solidity` (`src/evm.rs:178`), `Evm::create`/`try_call`/`call_with_logs`, `parse_solidity_trace_logs` (`src/test.rs:2274`).
- No SRS and **no proving**: frames are synthetic; circuits only need `keygen_vk_with_k` over `ParamsKZG::unsafe_setup` (pattern: `quotient_vm_test_vk`, `src/lowering/tests.rs:374`).

**Honest scope statement** (must appear in the new code's doc comments and the docs updates): for permutation/lookup/trash identities, `.expr` is re-parsed from the emitter's own Yul (`quotient_yul_expr`, `quotient.rs:947-953`), so the frame differential certifies the structural loop/table/chunking restructuring and the solc-compiled execution — *not* the per-identity formula, whose independent leg stays with the `rust-verifier-trace` proof differential against midnight-proofs. Gate identities (inline + native callbacks + interpreted) have genuinely independent typed lowering from `vk.cs().gates()` (`quotient_expr_from_plonk_expr`, `quotient.rs:788-795`), so for them this is a full independent check.

**The design in one sentence:** render the production evaluator, deploy it under revm, call it with artifact-seeded pseudorandom memory frames, and compare `[magic, -nu_y(x), selector_buckets]` (and, on a separate trace render, every per-identity LOG1 value) word-for-word against a Rust oracle that folds *all* identity expression trees over a flat frame-backed memory — the same Schwartz–Zippel argument `certify.rs` already uses, extended past the bytecode boundary to the compiled artifact.

All line numbers below were verified during exploration but should be re-located, not trusted, while implementing. Work only in `proofs/solidity-verifier/` (plus `ci.yaml` in Phase 4).

## Phase 1 — Oracle + frame machinery (no behavior change to production paths)

**1a. `QuotientProgramPlan::identities_in_execution_order()`** — `src/lowering/quotient_numerator/vm/mod.rs`, next to `execution_manifest()` (`:385-436`):
`pub(crate) fn identities_in_execution_order(&self) -> Result<Vec<(&QuotientIdentity, QuotientExecutionKind)>, String>` — the exact walk `execution_manifest` does today (inline → items with native markers expanded → structured tail), returning identity refs + kind. Rewrite `execution_manifest()` as a map over it so there is a single walk. Not cfg-gated. Existing `validate_execution_manifest` tests pin the behavior.

**1b. New module `src/lowering/quotient_numerator/vm/oracle.rs`**, declared `#[cfg(test)] pub(crate) mod oracle;` — deliberately free of solc/revm imports so a future opt-in render gate can promote it by changing the cfg. Contents:
- `pub(crate) trait QuotientOracleMemory { fn load(&mut self, ptr: u32) -> Fq; fn token(&mut self, token: u8, offset: u32) -> Fq; }` with an `impl for HashMap<u32, Fq>` preserving today's semantics (token panics — keeps existing literal-only unit tests honest).
- `pub(crate) struct QuotientFrameMemory<'a>` from `(frame, frame_base, token_bases)`: `load(ptr)` reads 32 BE bytes at `ptr - frame_base` (hard panic with the absolute address on out-of-frame reads), reduces mod `FR_MODULUS`; `token(t, off) = load(token_base(t) + off)` resolving the 9 tokens via `LoweringPlan::quotient_read_model().token_bases` (`plan.rs:365-403`). **Critique fix:** `debug_assert!` that any loaded word *outside* the VK-payload window is already canonical — the mod-r reduction is a safety net for VK-payload words the exprs never reference, not a semantic equivalence claim (EVM `sub(r, x)` on non-canonical words would diverge; the fill below guarantees canonicality).
- Promote from `src/lowering/tests.rs` (delete the originals, repoint call sites): `eval_quotient_expr_for_test` (`:4132`) → `eval_quotient_expr_with(expr, mem: &mut impl QuotientOracleMemory)`; `expected_linearization_artifacts_for_test` (`:4026`) → `expected_linearization_artifacts(identities, mem, y, selector_count) -> QuotientLinearizationArtifacts { identity_trace, main_numerator, selector_buckets, quotient_expected_eval }`. Keep `eval_quotient_program_artifacts_for_test`/`eval_quotient_vm_for_test` in `tests.rs` (bytecode-side twin; the compiled EVM replaces that leg — moving them churns 20+ call sites for nothing).
- `pub(crate) fn build_quotient_frame(external: &QuotientExternal, vk_mptr: usize, vk_bytes: &[u8], seed: [u8;32]) -> Vec<u8>`: fill EVERY 32-byte word at absolute address `a` with a canonical Fr derived like `QuotientRefMemory::derive` (`reference.rs:85-107`) under new domain `b"midfall/quotient-vm/frame-differential/v1"` keyed by `(seed, a)`; then overwrite the VK subrange with real `vk.bytes()` (const table + packed bytecode must be genuine). Do **not** special-case `QUOTIENT_EVAL_MPTR` — it's a write target; leaving it random freely detects a missing write (the oracle never reads it; `quotient_read_windows` excludes it, `plan.rs:437-445`). Whole-frame fill is sound because the oracle reads *through the same frame*, so both sides agree on every in-frame slot by construction, while out-of-window reads see adversarial data.
- `pub(crate) fn frame_differential_seed(base: [u8;32], iteration: u64) -> [u8;32]` (keccak, domain `b"midfall/quotient-vm/frame-differential-seed/v1"`); `base` = existing `certify::derive_certify_seed(&[&build], &all_surface_exprs, &vk.bytes())` so the assignment is artifact-bound with **all-surface** exprs bound in. Fully deterministic, no wall clock.

**1c. Share the SRS-free circuit** — new `#[cfg(test)] pub(crate) mod test_circuits;` in `src/lowering/`: move `QuotientVmTestCircuit` + `quotient_vm_test_vk()` (`lowering/tests.rs:281-384`) verbatim so `src/test.rs` can use them (sized via the `pub(crate)` `DEFAULT_*` consts to overflow inline+native budgets — guaranteed Inline + NativeIdentity + Interpreted coverage).

**2c. Main test** `quotient_frame_differential_matches_expr_oracle`: corpus = the 7 existing `supported_shape_evm_cases()` (widen `[ShapeFuzzCase; 7]` → `Vec`; select by **name**, not index, in `same_srs_distinct_shape_matrix_rejects_cross_wiring`) + `quotient_vm_test_vk()`. **2d. Negative controls** `quotient_frame_differential_detects_injected_faults` — 8 mutations, each asserted detected (Err or call failure), over `quotient_vm_test_vk()` + the "full mixed lookup permutation shape" case:

## Key decisions (and why)
1. **Test-side differential, not a render gate** — embedding solc+revm in `render()` inverts the P1.1 error-model direction and adds a heavyweight generator dependency for little gain over per-PR corpus coverage; the oracle module is structured so the strict gate stays a small follow-up.
2. **Solc-only gating** so the differential runs in the per-PR job — the audit's own observation is that the env-gated suite silently never runs; recreating that trap would defeat F1.
3. **Production render compared by return frame; trace render only for diagnostics** — the trace build is CALL-based and not production-identical; comparing the `trace:false` artifact's output is strictly stronger than the existing log-based differential, and `RenderDiagnostics` is always constructed explicitly because `Default` is feature-dependent.
4. **Whole-frame pseudorandom fill + real VK overlay** — random frames break the value correlations honest proofs satisfy (e.g. chunk-boundary products), catching wrong-slot bugs that cancel on honest traces; the VK subrange must be genuine or the VM can't run at all.
5. **Phases 1+2 land first and alone close the compiled-artifact half of F1** over the existing corpus (which already reaches all six surfaces — the kinds-union assertion verifies this on day one); Phase 3 then extends a proven differential instead of landing assertions against a stub.
